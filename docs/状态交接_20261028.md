## 一、今天真正解决了什么

### ✅ UFS 完全跑通（重大突破）

```
13.197  sd 0:0:0:0: [sda] Attached SCSI disk
12.086  sd 0:0:0:1: [sdb] Attached SCSI disk
12.072  sd 0:0:0:2: [sdc] Attached SCSI disk
12.088  sd 0:0:0:3: [sdd] Attached SCSI disk
12.133  sd 0:0:0:4: [sde] Attached SCSI disk
12.152  sd 0:0:0:5: [sdf] Attached SCSI disk

6 个 LUN / 125 个分区 / ufs_phy_gdsc [on]
系统进 initramfs 后稳定运行 60 秒以上，无 panic
```

**根因**：`CONFIG_PHY_QCOM_QMP_UFS` / `CONFIG_DRM_MSM` 等驱动全是 `=m`（模块），
但 initramfs 里 **0 个 .ko 文件** → 驱动永不加载 → UFS 一直停在 `-EPROBE_DEFER`，
看起来像"卡死"，其实是在等一个永远不会出现的驱动。

改成 `=y`（编进内核）后，UFS 立刻正常。

## 二、两条铁律（今天用 4 小时换来的）

### 铁律 1：DTB 是烤进 Mu 固件的，不是读 ESP 的

```
m2468.fdf:104:  SECTION RAW = m2468Pkg/FdtBlob/sm8550-meizu-21note.dtb
```

**改 dts 必须**：编 dtb → 拷进 `Mu-Silicium/Platforms/Meizu/m2468Pkg/FdtBlob/` → **重编 Mu** → 刷 `boot_b`

只刷 ESP 里的 `dtb` 文件 → **完全不生效**。
13:00 之后所有 dts 改动全部没生效，所以那几小时的结论互相矛盾。

**Mu 编译必须用普通用户**（root 没有 coloredlogs）：
```bash
wsl -e bash -lc "cd /home/shrp/Mu-Silicium && python3 build_uefi.py -d m2468 -r RELEASE"
```

### 铁律 2：改 =y 必须把整条依赖链一起改

单独设 `CONFIG_DRM_MSM=y` 会被 `make olddefconfig` 回退（因为 `DRM_KMS_HELPER=m`、
`DRM_DISPLAY_HELPER=m` 时它无法为 y），而且**连带把 `PHY_QCOM_QMP_UFS` 也关掉**。

必须按依赖顺序设：
`DRM` → `DRM_KMS_HELPER` → `DRM_DISPLAY_HELPER` → `DRM_DISPLAY_DP_HELPER`
→ `DRM_PANEL` → `DRM_PANEL_BRIDGE` → `DRM_MSM` → `DRM_MSM_DSI`
→ `PHY` → `PHY_QCOM_QMP` → `PHY_QCOM_QMP_UFS` → `SCSI_UFS_QCOM`

| 4 | **没有日志通道** | 无 UART，USB 不通，只能拍屏幕；内核日志被 `interconnect: sync_state() pending` 刷屏，关键行常被冲掉 | 🔄 子代理 A8 |

### display 的深层原因（已查明）

```
我们的 dts:  panel@0 compatible = "boe,meizu20-amoled-fhd"   ← 这是 m2381（魅族20）的屏！
m2468 真屏:  ILI7838E / TIANMA 1264×2780（A1 子代理从原厂树查明）
```

**实测**：把 `CONFIG_DRM_PANEL_BOE_MEIZU20=y` 编进去 → **内核进不到 init 直接崩**。
说明面板驱动与 m2468 的真实硬件不匹配，probe 阶段就炸。

## 六、晚上回来要商量的议题

1. **日志通道优先做哪一个**：如果 A6（USB）能修好，日志问题自动解决；否则走 A8 的 pstore/写 FAT32 方案。要不要先全力修 USB？
2. **display 要不要投人力**：m2468 的真实面板是 ILI7838E/TIANMA，需要**从原厂内核源码或反编译里挖 DSI 参数**才能写驱动。这是工作量最大的一块，且不影响"系统能跑"。要不要先跳过显示，优先做 rootfs + 网络？
3. **下一步的里程碑定义**：按 A3 的建议，UFS 通了就该上真正的 rootfs（nura 形态：`root=` 直挂 UFS，不要 initramfs）。要不要现在就开始做 rootfs？
4. **ESP 位置**：现在用 `rawdump`（非标准），nura 用 `recovery_a`（100MiB FAT32，MsBootPolicy 标准备援路径）。要不要迁移？
