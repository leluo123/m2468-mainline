## 四、关键技术点（都是踩出来的）

### 1. initramfs 改了必须重新打包 cpio.gz（最大的坑）

```bash
cd /home/shrp/_ird_check
find . -print0 | cpio --null -o -H newc | gzip -9 > /home/shrp/initramfs.cpio.gz
```

**这个坑让 E17–E21 五轮实验全部白跑** —— 改了 `_ird_check/init` 但没重新打包，
内核一直用 14:06 那份旧 init（md5 `ede6cdc9`），所有 chroot 逻辑从未执行。
**验证方法**：解压 cpio.gz 检查 init 的 md5 是否是新的。

### 2. chroot 不能用 `exec`（会砖机）

E22 用 `exec chroot /newroot /sbin/init` → Ubuntu init 崩溃 → PID 1 退出 → kernel panic
→ `panic=-1` 不重启 → 设备完全失联（无 USB/无串口），必须拔电。

**正确做法**（E23）：
```sh
setsid chroot /newroot /sbin/init < /dev/null > /dev/null 2>&1 &
CHPID=$!
sleep 10
if kill -0 $CHPID 2>/dev/null; then
    wait $CHPID     # PID 1 仍是 initramfs，崩了只退 shell
else
    echo "chroot died, fallback to shell"
fi
```

### 3. tty 仲裁：agetty 和 initramfs shell 不能抢串口

- chroot 前**不要** `exec < $GS > $GS`（否则 agetty 抢不到）
- chroot 失败后再把 shell 接到 ttyGS0

### 4. userdata 分区是 `/dev/sda23`（不是 sda1/sda2）

- `fastboot flash userdata` 写的是 **232GB 分区的前 8GB**
- initramfs 里扫分区必须包含 `sda23`，或者用 `/dev/sd*[0-9]*` 全扫

### 5. ext4 镜像里写文件必须验证落盘

第一次写 rootfs init 时，`cp` + `sync` + `umount` 之后文件是**全零**（2212 字节的 NULL）。
`img2simg` 把空洞原样保留，刷进手机就是空文件。
**修法**：写一个 1MB flush 块 + 双 sync + **重新挂载读回验证**。

### 6. Ubuntu base 不带 init

`ubuntu-base` 是最小集，**没有 systemd、没有 busybox、没有 /sbin/init**。
需要自己写 init（`/usr/sbin/init`，`/sbin` 是 usrmerge 符号链接到 `usr/sbin`）。

我们写的 init 做：mount 伪文件系统 → ldconfig → 拉起 `agetty ttyGS0` 自动登录 root。
