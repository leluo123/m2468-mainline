## 一、今晚的核心突破：USB CDC-ACM 打通

### 1.1 完整配方（六件套，来自 fuxi 真机验证）

```dts
&usb_1 {
	dr_mode = "peripheral";
	/delete-property/ usb-role-switch;
	phys = <&usb_1_hsphy>;              /* ★ 只留 USB2 PHY */
	phy-names = "usb2-phy";
	maximum-speed = "high-speed";
	qcom,select-utmi-as-pipe-clk;       /* ★ UTMI 当 pipe clk */
	status = "okay";
};

&usb_dp_qmpphy {
	status = "disabled";                /* ★ 不碰 USB3/DP combo */
};
```

内核配置：`CONFIG_USB_G_SERIAL=n`

### 1.2 三层嵌套的失败原因（之前只改 dr_mode 完全无效）

1. `drivers/usb/dwc3/drd.c:546-552` —— DT 里有 `usb-role-switch` 时 `dwc3_drd_init()` 立刻 `return dwc3_setup_role_switch()`，**`dr_mode` 完全不参与**
2. `drivers/usb/dwc3/dwc3-qcom.c:686-696` —— 只有 `usb_get_dr_mode()==PERIPHERAL` 才在 probe 阶段调 `dwc3_qcom_vbus_override_enable(qcom,true)` 伪造 VBUS；OTG 分支要等 `pre_set_role`/`pre_run_stop`，而 pmic-glink 已死（`failed to init pdr`）
3. 即使前两条都对，`phys` 里还挂着 `usb_dp_qmpphy` —— **它起不来，整个 dwc3 probe 依然失败**

### 1.3 四个曾误导判断的假信号

| 现象 | 真相 |
|---|---|
| `/dev/ttyGS0` 存在 | **假证据**。configfs `mkdir functions/acm.*` 那一刻 `f_acm.c:891 gserial_alloc_line()` 就建了它，与 bind 无关 |
| `couldn't find an available UDC or it's busy` | **不代表被占用**。`core.c:1760-1769` 在 `!driver->is_bound` 时报的人为日志，三种根因共用且错误被 driver core 吞掉 |
| `state=` 读出空串 | **读失败**，不是驱动状态。`usb_state_string()` 源码上永远返回非空（`common.c:160-179`） |
| `/sys/class/udc/xxx` 目录存在 | **只证控制器注册了**，不含任何绑定信息 |

## 二、第 5 次「模块腿」：GPUCC

### 2.1 问题

```
arm-smmu 3da0000.iommu: probe with driver arm-smmu failed with error -110
adreno 3d00000.gpu:     deferred probe timeout
adreno_gmu 3d6a000.gmu: deferred probe timeout
```

`3da0000.iommu` 是 **GPU 专用 AMMU**（主 SMMU `15000000` 正常）。

### 2.2 根因

```
CONFIG_SM_GPUCC_8550 = m      ← GPU 时钟控制器是模块，initramfs 里 0 个 .ko
```

因果链：
```
gpucc-sm8550 无 driver
  → 3da0000.iommu 拿不到 clocks
  → 永久 -EPROBE_DEFER
  → deferred 超时 → -110
  → adreno / adreno_gmu 连带 deferred
```

### 2.3 已修的版本

`★待刷_v35_GPUCC.img` —— `CONFIG_SM_GPUCC_8550=y`，System.map 验证 `gpu_cc_sm8550_driver_init` 存在（11 个符号），八项门槛 8/8，config md5 一致。

### 2.4 连锁推论：cpufreq 可能自动解决

`devices_deferred` 现在只剩 1 项：

```
17d91000.cpufreq  qcom-cpufreq-hw: Failed to find icc paths
```

但日志里有这个循环：

```
gcc-sm8550 100000.clock-controller: sync_state() pending due to 3da0000.iommu
gcc-sm8550 100000.clock-controller: sync_state() pending due to a90000.i2c
```

**`gcc` 在等 iommu 和 i2c，`cpufreq` 在等 `gcc`。** GPUCC 修好后 iommu 起来 → gcc sync_state 完成 → cpufreq 可能自动好。

另：`1c00000.pcie` 在运行过程中**自行从 deferred 里消失了**（重试成功），说明 deferred probe 还在工作。

## 三、屏幕关闭方法（已验证）

```sh
# 1. 解绑 fbcon，停止重绘
echo 0 > /sys/class/vtconsole/vtcon1/bind

# 2. 清零 framebuffer（13 MB）
dd if=/dev/zero of=/dev/fb0 bs=1M count=13
```

**只做第 2 步无效** —— init 每次写 `/dev/tty0` 就等于让 fbcon 重绘，会把内容画回来。

`/sys/class/backlight/` 是空的（display 没通，没有背光驱动），所以无法软件调亮度。但 AMOLED 全黑像素不发光，黑屏即可避免烧屏。

`/sys/class/graphics/fb0/blank` 写 1 会报 `Invalid argument`（efifb 不支持该级别）。

## 七、已经踩过的 5 次「模块腿」（同一类坑，务必记住）

| # | 配置项 | 后果 |
|---|---|---|
| 1 | `CONFIG_PHY_QCOM_QMP_UFS=m` | UFS PHY 不加载 → `ufshcd` 永久 deferred → UFS 卡死 |
| 2 | `CONFIG_PHY_SNPS_EUSB2=not set` | dwc3 拿不到 HS PHY → `Failed to register DWC3 Core` |
| 3 | `CONFIG_DRM_MSM=m` | display 无驱动 |
| 4 | `CONFIG_SM_DISPCC_8550=m` | dispcc 缺席 → mdss 拿不到 clocks/power → -110 |
| 5 | `CONFIG_SM_GPUCC_8550=m` | gpucc 缺席 → GPU AMMU 拿不到 clocks → -110 → adreno deferred |

**排查铁律**：看到某个设备 deferred 或 -110，先查它依赖的 provider 是不是 `=m`，而 initramfs 里没有 `.ko`。

```bash
# 一次性列出所有可疑的 =m
grep -oP '^CONFIG_\w+(?==m$)' .config | grep -iE 'qcom|sm8|phy|dispcc|gpucc|gcc'
```
