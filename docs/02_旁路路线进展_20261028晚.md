## 一、今天最重要的成果（两个）

### 成果 1：根因 100% 确认

实测屏幕日志（把 PmicDxe 恢复回去的那次）：

```
CPU Vectors region not present in cfg file !
SPMI bus busy × 4
Synchronous Exception at 0x00000000C66DC8A0
```

与 `移植记录_20261027.md` 的预言**逐字吻合**，连地址 `0xC66DC8A0` 都一致。

**因果链**：

```
ABL 按「即将跳 Android 内核」的方式初始化 SPMI arbiter
  → Mu 的 SPMIDxe 期望接手干净状态 → 报 SPMI bus busy × 4
  → PmicDxe 拿不到有效句柄 → 同步异常 @0xC66DC8A0 → CpuDeadLoop
  → PMIC 从未初始化 ⇒ 所有 LDO 不供电
  → 内核 probe 任何外设读寄存器 → synchronous external abort
```

**⇒ 之前所有的 `geni_i2c_probe` 崩溃、`qcom_smd_edac` 崩溃、所有 dts 改动、6.14 vs 7.3 之争，全都在给这个根因打补丁。**

### 成果 2：旁路路线打通（24 秒 → 37.5 秒）

**原理**：既然 PMIC 不供电，那就把需要供电的外设逐个关掉，让内核不去碰它们。

| 版本 | 关掉的 | 跑到 | 崩点 |
|---|---|---|---|
| 上午所有版本 | 无 | **24 秒** | `geni_i2c_probe` SError |
| **B** | 10 个 I2C SE | **37.2 秒** | IPA 之后 |
| **B2** | +mpss/adsp/cdsp/ipa | **37.5 秒** | `a600000.usb` |
| **B3** | +gpu/usb/camss | 37.2 秒（同 B2，见下方教训） | video-codec |
| **B4** | +iris(video-codec) | 35.9 秒 | `ac0000.geniqup` 之后 |

**关键**：从 24 秒到 37.5 秒，跨过 I2C、SMMU、UFS、regulator、IPA、remoteproc **六个子系统，全程零 SError**。

这彻底证实根因判断，也证明「逐个关外设」这条旁路是通的。

## 二、今天踩的坑（都写进流程了）

| 坑 | 现象 | 解法 |
|---|---|---|
| **Mu 也用 FdtBlob** | 关掉整个 i2c hub → Mu 自己几秒就重启 | 只关 SE，保留 hub |
| **标签不等于节点名** | `&video_codec`/`&isp`/`&usb_1` 都不存在 | 真实标签：`iris`/`camss`/`gpu`；USB 用路径 `&{/soc@0/usb@a600000}` |
| **dts 里已有 &iris 块** | `if '&iris {' not in s` 判断跳过，改动静默失败 | 直接 append，最后一条生效 |
| **dtb 不重编** | dts 改了但 dtb 时间戳不变，刷进去是旧的 | `rm -f dtb && touch dts && make` |
| **root 跑 Mu 编译失败** | `ModuleNotFoundError: coloredlogs` | Mu 必须用普通用户 `wsl -e bash -lc` |
| **Windows 路径在 root WSL 里无效** | `cp: 无法创建 'C:/Users/...'` | 一律用 `/mnt/c/...` |
| **子 shell 变量丢失** | `(A=x \|\| B=x) && $PY` → rc=127 | 不用括号 |

## 四、下一步（两条路，A 和 B）

### A. 修 SPMI（根治，1–2 天）

在 `BootShim.S` 的 `br x5` 之前插 SPMI arbiter 复位序列。

**原料已备**：
- `abl.img` → ELF32 → `unwrap-qcom-pil.py` → 1MB FV + 610,504 B LinuxLoader PE
- **已确认：LinuxLoader 里不含 SPMI 代码**（0 条 SPMI 字符串、0 处 0xc42d000 引用、0 处 base+0xE00 写）
- **⇒ SPMI 初始化在 XBL 里，需要读 `xbl_a` 分区继续挖**

**下一步动作**：`adb shell su -c 'dd if=/dev/block/by-name/xbl_a of=/data/local/tmp/xbl.img'`，解包后找 SPMI arbiter 初始化。

### B. 继续旁路（0.5–1 天，更快）

继续关外设直到跑到 initramfs。跑到之后：
- 屏幕会有 initramfs 输出（不再依赖拍照）
- 可以启用 pstore/ramoops 把完整 dmesg 写盘
- USB gadget（initramfs 自带）能提供串口通道

**下一个要关的**：`geniqup@ac0000`（第二个 I2C hub）本体、`a00000.dma-controller`（GPI）。

**风险**：`geniqup@9c0000` 不能关（Mu 需要）；关 `ac0000` 要注意 Mu 是否也用它。

### B+ 更聪明的做法

**让内核 panic 时把日志写进 ramoops**，然后**用我们的内核自己读**（而不是 Android 内核）。

需要：
1. 在 dts 里加正确的 `ramoops` reserved-memory 节点
2. initramfs 里加一段脚本读 `/sys/fs/pstore/` 并写到 ESP 分区

这样每轮实验都能拿到完整日志，不用再靠拍照。
