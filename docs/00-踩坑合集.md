# 踩坑合集

按「症状 → 真实原因 → 正确做法」记。全部是在这台机器上真实踩过并付出过代价的。

---

## 一、引导与镜像

### 1. ESP 里放了 dtb → 直接炸机
**症状**：换了内核，屏幕完全不亮，串口也没输出。
**原因**：U-Boot/ABL 会**优先读取 ESP 上的 dtb**，用它覆盖运行时 DT。
**做法**：ESP 里只放两样东西 —— `EFI/BOOT/BOOTAA64.EFI` 和 `initramfs.cpio.gz`。**绝不放 dtb。**

### 2. 把 `Image` 直接改名成 `BOOTAA64.EFI`
**症状**：fastboot 刷写正常，重启后毫无反应。
**原因**：EFI stub 需要的是 **EFI zboot 容器**（`vmlinuz.efi`），不是裸 `Image`。
**做法**：`make Image vmlinuz.efi`（CONFIG_ZBOOT + zstd），拿 `vmlinuz.efi` 当 `BOOTAA64.EFI`。
自查：文件头必须是 `MZ`。

### 3. 每次实验换 initramfs，结果无法定位变量
**原因**：initramfs 里也有大量逻辑，换它等于同时改两个变量。
**做法**：实验期间 **initramfs 冻结成原版**（我们用的是 `1,067,119 B / md5 1d253304`），
唯一变量只允许是 `BOOTAA64.EFI`。

### 4. `make ... | tail` 吞掉退出码，打出旧内核却以为成功
**症状**：改了代码，刷进去完全没变化。查 md5 才发现是上一次的镜像。
**原因**：`set -e` 对管道只看最后一个命令（`tail`）的退出码。
**做法**：`make` 单独跑并检查 `$?`，打包前后 **比对 kernel md5**，变了才算编译成功。

### 5. 中文文件名传给 Windows 原生 `fastboot.exe` → 静默失败
**做法**：先 `cp` 成 ASCII 名，再刷。也别用 `/c/...` 风格路径喂原生 exe（会被拼成 `C:\c\...`）。

### 6. 中文路径 loop 挂载失败
**症状**：`mount -o loop '★待刷_xxx.img' /mnt` 报「设置回环设备失败」。
**做法**：FAT32 镜像根本不用挂载 —— `mcopy -i img ::/文件 /输出`、`mdir -i img ::/` 直接读写。

### 7. 刷完忘了切 slot
**做法**：刷完必须 `fastboot --set-active=a`。（这台机器 slot b 不可靠。）

### 8. 电量低于 25% 刷机
**症状**：刷完黑屏，串口 3.70V 时拉不起来，疑似启动电流拉穿 PMIC 阈值。
**做法**：刷前查电量，<25% 不刷。

## 二、串口

### 9. 串口发 heredoc → shell 卡在续行状态
**症状**：之后发的每条命令都没反应，提示符变成 `>`。
**做法**：先把脚本**落成文件**再执行；卡住了发一次 Ctrl+C。

### 10. 大脚本直接粘贴 → 丢字符（表现为「脚本根本没跑」）
**做法**：base64 分块传输，**每块 ≤1200 字符**（超了会静默丢字符）。见 `scripts/serial/send_long.ps1`。

### 11. 启动「太慢」，每行 dmesg 间隔 15 秒
**原因**：不是内核慢，是**串口控制台阻塞** —— 内核 printk 写串口等流控。
**做法**：别去优化启动，先看是不是串口在拖。真正落到 userspace 的时间要看 `switch_root` 之后。

### 12. 进 fastboot 后串口 COM 号消失
**做法**：每次重新 `[System.IO.Ports.SerialPort]::getportnames()`，别硬编码 COM16。

## 三、显示与触摸

### 13. 照抄魅族 20（BOE）的面板参数 → 不亮
**原因**：21 Note 是**天马 ILI7838E LTPO**，时序、DSC、初始化序列全都不同。
**做法**：参数只能从原厂 dtbo 反推 + 实测，不能跨机型抄。

### 14. cmd mode 下把 `BURST_MODE` 去掉 → 黑屏
**做法**：**cmd mode 必须保留 BURST_MODE**。ADFR 开关同理，18 条/195B 那组不能少。

### 15. 读未映射的 DSI 寄存器 → 总线挂死
**做法**：别去读 `0x84` / `0x100` / `0x104` / `0x330` 这些没映射的寄存器，会直接把 DSI 搞挂。

### 16. 用 `fb0/blank` 触发 modeset → 花屏/不恢复
**做法**：必须 `systemctl restart greetd`。

### 17. `phoc.ini` 的 mode 没带 `Hz` 后缀 → 不生效
**做法**：写 `1264x2780@120.00Hz`，少这个后缀 phoc 直接忽略。

### 18. 触摸没反应，以为是 GENI FIFO 问题
**真相**：是 **QUP-GPI** 路径（`grab_gpi_chan` 失败 → `FIFO_IF_DISABLE_RO=1` → `-110`）。
**细节**：`docs/★触摸根因_QUP-GPI_20261031.md`。别再从 GENI FIFO 方向找。

---

### 19. GPU 报 `failed to load a740_sqe.fw`，但文件明明在 rootfs 里
**症状**：`dmesg` 里
```
Direct firmware load for qcom/a740_sqe.fw failed with error -2
[drm:adreno_request_fw] *ERROR* failed to load a740_sqe.fw
```
可 `/lib/firmware/qcom/a740_sqe.fw` 确实存在（76724 字节）。

**真因**：这条错误发生在 **11.9 秒**，那时还在 **initramfs** 里 ——
`msm` 驱动是早期加载的，`request_firmware` 找的是 initramfs 里的
`/lib/firmware/qcom/a740_sqe.fw`，而固件只存在于真正的 rootfs 上。
`error -2` 是 ENOENT，跟文件在不在 rootfs 无关。

**判断 GPU 到底有没有在用**（别只看这条 ERROR）：
```bash
ls -l /proc/$(pgrep -f bin/phoc|head -1)/fd | grep dri
```
- 拿到 `renderD128` 的 fd → 合成器在用 GLES，**GPU 是工作的**
- 只有 `card0` → 才真的是纯 KMS/软件

再交叉验证：`cat /sys/class/devfreq/3d00000.gpu/cur_freq`（有频率说明 GPU 供电跑了）、
`dmesg | grep bound`（应看到 `bound 3d00000.gpu (ops a3xx_ops)` 和 `bound 3d6a000.gmu`）。

**教训**：`dmesg` 里的 ERROR 要看**时间戳对应哪个阶段**（initramfs / rootfs）。

## 四、电源

### 20. udev 用 `ATTR{name}` 匹配电源 → 规则永不触发
**原因**：`power_supply` 设备的 `name` 是 `ENV` 不是 `ATTR`。
**做法**：`ENV{POWER_SUPPLY_NAME}=="..."`。
**验证**：先故意写错值 → `udevadm trigger` → 看它是否被纠正回来。**写完读回一遍不算验证**（那是假成功）。

### 21. 快充只有 900mA
**根因链**：DTS 删掉 `usb-role-switch` → UCSI `EPROBE_DEFER` → `PPM init failed` → 掉到 900mA。
**代价**：补回来后 pmic-glink 会堵死约 7 分钟。要改就得全量重编 + 接受这个副作用。

### 22. performance governor 锁频 → 随机重启
**做法**：限频能缓解但不能根治。

### 23. 把 MX 电源域钉在高档位 → 直接起不来
**症状**：刷完内核完全无输出，掉进 fastboot。
**原因**：MX 是 DDR/LLCC 的关键域，钉到 NOM_L1 会破坏内存时序。
**做法**：**CX 可以试，MX 绝对别碰。**

## 五、基带（这一块坑最多）

### 24. 伪造 `rf_static_464_00_00.mbn` → PLL 周期性崩溃
**原因**：出厂固件只有 463/473，拿别的冒充会让校准和硬件不匹配。
**做法**：**永远删掉假文件**，让 modem 用 `so/464_0_0.mbn` 的内置默认校准。
（这条我们犯过两次——文件被放回去后崩溃立刻复发。）

### 25. 用 ModemManager / NetworkManager 拨号 → 把 modem 拖崩
**原因**：MM **不做 Bind Mux**，直接拨号必失败，而且会把 modem 搞崩（崩溃计数从 8 涨到 10）。
**做法**：`nmcli device set qrtr0 managed no`，数据自己用 WDS 起。

### 26. WDS mux 固定不变 → `INTERNAL(3)`
**原因**：modem 重启后旧 mux 绑定失效。
**做法**：**每次绑定都用新的 mux**（递增，或冲突时换）。

### 27. 数据脚本一退出网就断
**原因**：WDS 客户端随进程释放，数据调用被拆掉。表现是 `TX dropped` 有值、`RX: 0`。
**做法**：写**常驻 daemon** 持有调用（`userspace/data_daemon.py`）。

### 28. daemon 的 socket 是模块级全局 fd → 基带崩一次就永久废掉
**症状**：射频恢复了，数据死活连不上，daemon 一直重试也起不来。
**原因**：`fd = open_sock()` 在 import 时开一次，modem 崩过之后这个 fd 就失效了。
**做法**：**每次射频恢复后重启 data 服务**。

### 29. `qmicli --dms-get-operating-mode` 读数不可信
**做法**：用 raw QMI（`userspace/dms_mode.py`）看 `MODE=0x01`，配合 `Registration` / `Radio interfaces` 判断。

### 30. 跑 `--uim-change-provisioning-session` 把 SIM 弄成 eUICC
**症状**：`Is eUICC: yes`、`Num apps: 0`、AID 变成乱码、PIN `not-initialized`。
**做法**：别用它。要上下电用 `--uim-sim-power-off` / `--uim-sim-power-on`。
而且**不能在射频初始化后跑**，会打断 RF 初始化。

### 31. 冷启动后 SIM ready 但射频是 `none`
**原因**：没有任何东西去拉起射频。
**做法**：DMS 上下电就是开关 ——
```
qmicli -d qrtr://0 --dms-set-operating-mode=low-power
sleep 8                      # 这个 sleep 不能省，短了会抢跑
qmicli -d qrtr://0 --dms-set-operating-mode=online
```

### 32. rmtfs 报 `open /boot/modem_fs1 => 0`，EFS 其实没通
**原因**：`-o` 目录里必须存在**名字就叫** `modemst1` / `modemst2` 的文件。
**做法**：`/var/lib/rmtfs-efs/modemst1|modemst2` 做软链，unit 里只能有一条 `ExecStart`。

### 33. tqftpserv 服务根目录不存在 → 射频起不来
**做法**：`/readonly/firmware/image/` → `/lib/firmware/qcom/sm8550/meizu/modem_pr`，
`/readwrite/` → `/tmp/tqftpserv`（tmpfs）。

### 34. 改 EFS 前不备份
**做法**：写前全量快照 + 逐条读回校验。`modemst1`/`modemst2` 会被改，`fsg`/`fsc` 不碰。

### 35. 8 个 `yes` 压测把机器打挂
**症状**：设备直接失联，约 4 分钟自己恢复（OOM/watchdog）。
**做法**：压测用 2 核 30 秒这种温和量。

## 六、网络

### 36. 网络图标一直是感叹号
**两层原因**：
1. NetworkManager 默认 `response=OK`，而 `generate_204` 返回的是空 204 → 判定 `portal`。
2. 数据绕开 MM 自起，NM 看到 `qrtr0:gsm:disconnected`。

**做法**：`[connectivity] uri=http://<国内可达的 generate_204>` + **`response=` 留空**；
再把 `qrtr0` 设 unmanaged。根本解决仍要靠 modem 稳定注册。

### 37. 中文输入法/商店 装不上
**原因**：磁盘 91% 满。先清盘。

## 七、工具与环境

### 38. 多设备同时连着，危险命令打错机器
**做法**：`adb` / `fastboot` 的破坏性命令**必须带 `-s <序列号>`**。
注意 **adb 序列号和 fastboot 序列号不是同一个**。

### 39. WSL 里 `sudo` 编译过一次，之后普通用户编译全挂
**症状**：`include/config/kernel.release` 各种 Error 2。
**做法**：`sudo chown -R $(id -un):$(id -gn) <内核树>`。

### 40. 树外模块 vermagic 不匹配
**做法**：`make modules ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-`，
编完 `modinfo` 看 vermagic 要和 `uname -r` 一致。
另外：WSL 里的 vmlinux 配置如果和跑着的内核不同（比如 PSI 开关不一样），
模块会出现 `psi_memstall_enter undefined` —— 那就得全量重编。

## 八、方法论（这几条比技术更值钱）

1. **一次只改一个变量**，先跑对照组。改两个东西出问题就白改。
2. **「写进去」不等于「生效了」** —— 参数存在、返回 0、debugfs 有个数字，都不代表硬件吃到了。
   要拿到**能区分两种情况的观测**（我们最后是靠 `pr_info` 打出 `level_count` 和实际 corner 才确定下限真的生效）。
3. **负面结果要留证据**。这个项目里「排除某假设」的日志和「某功能可用」的日志一样值钱，
   否则下一次会有人把同样的坑再踩一遍。
4. **固件/校准类文件不要猜**。猜出来的「看起来对的」文件比缺失更危险。
