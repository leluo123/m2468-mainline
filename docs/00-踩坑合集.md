# 踩坑记录

四十条，全是在这台机器上真踩过的。按「怎么发现、到底是什么、后来怎么写」来说，
没踩过的别往上凑。

## 一、引导和镜像

**1. ESP 里塞了 dtb，机器直接不亮**

串口也一点输出都没有，一开始以为是内核编坏了。其实 ABL 会优先去读 ESP 上的 dtb，
拿它覆盖运行时 DT，当场炸。ESP 里只该放两样东西：`EFI/BOOT/BOOTAA64.EFI` 和 `initramfs.cpio.gz`。

**2. 把 `Image` 改名成 `BOOTAA64.EFI`**

刷写一切正常，重启毫无反应。EFI stub 要的是 EFI zboot 容器（`vmlinuz.efi`），裸 `Image` 不行。
`make Image vmlinuz.efi` 之后拿 `vmlinuz.efi` 去当 `BOOTAA64.EFI`，文件头是 `MZ` 就对了。

**3. 每次实验顺手换了 initramfs**

结果出问题根本不知道是内核还是 initramfs 的锅。后来把 initramfs 冻死在一个版本
（`1,067,119 B`，md5 `1d253304`），实验期间只动 `BOOTAA64.EFI` 一个变量。

**4. `make ... | tail` 把退出码吃了**

改完代码刷进去毫无变化，查 md5 才发现刷的是上一次的镜像。`set -e` 对管道只看最后一个命令
（也就是 `tail`）的状态码，`make` 失败了它照样返回 0。现在 `make` 单独跑并检查 `$?`，
打包前后比一次 kernel md5。

**5. 中文文件名喂给 Windows 原生 `fastboot.exe`**

不报错，也不干活。先 `cp` 成 ASCII 名再刷。同理别用 `/c/...` 风格路径喂原生 exe，
会被拼成 `C:\c\...`。

**6. 中文路径 loop 挂载失败**

`mount -o loop '★待刷_xxx.img'` 报「设置回环设备失败」。FAT32 镜像根本不用挂：
`mcopy -i img ::/文件 /输出`、`mdir -i img ::/` 直接读写。

**7. 刷完忘了切 slot**

这台机器 slot b 不可靠，刷完必须 `fastboot --set-active=a`。

**8. 电量不到 25% 就刷**

刷完黑屏，串口显示 3.70V 才拉起来，看着像启动电流把 PMIC 阈值拉穿了。现在刷前先看电量。

## 二、串口

**9. 用 heredoc 往串口发脚本**

发完之后每条命令都没反应，提示符变成 `>`，shell 卡在续行状态里。脚本先落成文件再执行，
卡住了发一次 Ctrl+C。

**10. 大脚本直接粘贴进串口**

会静默丢字符，表现是「脚本根本没跑」。用 base64 分块传，每块不超过 1200 字符。

**11. 觉得开机太慢**

dmesg 每行间隔 15 秒，看着像内核卡住了。其实是串口控制台阻塞，printk 在等流控。
判断真实启动时间要看 `switch_root` 之后。

**12. 进 fastboot 后还硬编码 COM16**

设备一变模式 COM 号就变了。每次重新 `[System.IO.Ports.SerialPort]::getportnames()`。

## 三、显示和触摸

**13. 照抄魅族 20 的面板参数**

21 Note 是**天马 ILI7838E LTPO**，魅族 20 是 BOE，时序、DSC、初始化序列全不一样。
参数只能从原厂 dtbo 反推再实测，跨机型抄必翻车。

**14. cmd mode 下去掉 `BURST_MODE`**

黑屏。cmd mode 必须保留 BURST_MODE，ADFR 也是，18 条那组少一条都不行。

**15. 去读没映射的 DSI 寄存器**

`0x84`、`0x100`、`0x104`、`0x330` 这几个读下去总线直接挂死。

**16. 用 `fb0/blank` 触发 modeset**

花屏，而且回不来。要重来就 `systemctl restart greetd`。

**17. `phoc.ini` 的 mode 没写 `Hz`**

写成 `1264x2780@120.00` 不生效，必须是 `1264x2780@120.00Hz`。少了后缀 phoc 直接忽略。

**18. 触摸没反应就往 GENI FIFO 方向查**

真相是走 QUP-GPI：`grab_gpi_chan` 失败，然后 `FIFO_IF_DISABLE_RO=1`，最后 `-110`。
细节在 `docs/★触摸根因_QUP-GPI_20261031.md`。

**19. GPU 报 `failed to load a740_sqe.fw`，可文件明明在**

```
Direct firmware load for qcom/a740_sqe.fw failed with error -2
[drm:adreno_request_fw] *ERROR* failed to load a740_sqe.fw
```

`/lib/firmware/qcom/a740_sqe.fw` 确实存在，76724 字节。后来看时间戳才明白：
这条错误发生在开机第 11.9 秒，那会儿还在 initramfs 里。`msm` 驱动加载得早，
`request_firmware` 找的是 initramfs 里的路径，固件只在真 rootfs 上，`error -2` 就是 ENOENT。

所以别光看这条 ERROR 就判 GPU 没起来。看合成器有没有打开 render 节点：

```bash
ls -l /proc/$(pgrep -f bin/phoc|head -1)/fd | grep dri
```

有 `renderD128` 就是走 GLES，GPU 是干活的。只有 `card0` 才是真的纯 KMS。
再交叉看一下 `cat /sys/class/devfreq/3d00000.gpu/cur_freq` 有没有频率。

教训是，dmesg 里的 ERROR 得对一下时间戳落在哪个阶段。

## 四、电源

**20. udev 规则用 `ATTR{name}` 匹配电源**

永远不触发。`power_supply` 设备的 `name` 是 ENV 不是 ATTR，得写 `ENV{POWER_SUPPLY_NAME}`。
验证方法也有讲究：先故意写错值，`udevadm trigger`，看它有没有被纠正回来。
写完读一遍确认，那叫自欺。

**21. 快充只有 900mA**

DTS 删掉 `usb-role-switch` 之后，UCSI `EPROBE_DEFER`，`PPM init failed`，掉到 900mA。
补回来 pmic-glink 会堵死大概七分钟，要改就得全量重编并接受这个副作用。

**22. performance governor 锁频**

随机重启的诱因之一。限频能缓解，但没根治。

**23. 把 MX 电源域钉在高档位**

刷完完全没输出，掉进 fastboot，以为砖了。MX 是 DDR/LLCC 的关键域，钉到 NOM_L1
会破坏内存时序。CX 可以试，MX 别碰。

## 五、基带

**24. 伪造 `rf_static_464_00_00.mbn`**

出厂固件只有 463 和 473，拿别的冒充会让校准跟硬件对不上，表现是 PLL 周期性崩溃。
永远删掉假文件，让 modem 用 `so/464_0_0.mbn` 的内置默认校准。这条我们犯了两次，
文件被放回去之后崩溃立刻复发。

**25. 用 ModemManager 或 NetworkManager 拨号**

MM 不做 Bind Mux，拨号必失败，还会把 modem 拖崩（崩溃计数从 8 涨到 10）。
`nmcli device set qrtr0 managed no`，数据自己用 WDS 起。

**26. WDS 的 mux 一直用同一个值**

`INTERNAL(3)`。modem 重启之后旧 mux 的绑定就失效了，每次绑新的（递增，冲突了也换）。

**27. 数据脚本一退出网就断**

WDS 客户端跟着进程释放，数据调用被拆掉。表现是 `TX dropped` 有值但 `RX: 0`。
得写常驻 daemon 把调用持住，`userspace/data_daemon.py` 就是干这个的。

**28. daemon 的 socket 是模块级全局 fd**

`fd = open_sock()` 在 import 的时候开一次，modem 崩过之后这个 fd 就废了，
daemon 再怎么重试都连不回来。所以射频恢复之后要重启 data 服务。

**29. 相信 `qmicli --dms-get-operating-mode` 的读数**

它显示 low-power，实际是 online。要用 raw QMI（`userspace/dms_mode.py`）看
`MODE=0x01`，再配合 `Registration` 和 `Radio interfaces` 判断。

**30. 跑 `--uim-change-provisioning-session`**

SIM 变成 `Is eUICC: yes`、`Num apps: 0`、AID 一串乱码、PIN `not-initialized`。
别用它。要上下电用 `--uim-sim-power-off` / `--uim-sim-power-on`，而且不能在射频
初始化之后跑，会打断 RF 初始化。

**31. 冷启动后 SIM ready 但射频是 `none`**

没有任何东西去拉起射频。开关是 DMS 上下电：

```
qmicli -d qrtr://0 --dms-set-operating-mode=low-power
sleep 8
qmicli -d qrtr://0 --dms-set-operating-mode=online
```

那个 sleep 8 不能省，短了会抢跑。

**32. rmtfs 报 `open /boot/modem_fs1 => 0`，以为 EFS 通了**

其实没通。`-o` 目录里必须存在名字就叫 `modemst1` / `modemst2` 的文件，
做一个软链就行。unit 里只能有一条 `ExecStart`。

**33. tqftpserv 的服务根目录不存在**

射频起不来。要把 `/readonly/firmware/image/` 指到
`/lib/firmware/qcom/sm8550/meizu/modem_pr`，`/readwrite/` 指到 `/tmp/tqftpserv`（tmpfs）。

**34. 改 EFS 之前没备份**

写前要全量快照，写完逐条读回校验。`modemst1`/`modemst2` 会被改，`fsg`/`fsc` 不要碰。

**35. 开 8 个 `yes` 压测**

设备直接失联，大概四分钟后自己回来，OOM 加 watchdog。压测用两核 30 秒这种量级就够了。

## 六、网络

**36. 网络图标一直带感叹号**

两层原因叠在一起。一是 NetworkManager 默认 `response=OK`，而 `generate_204` 返回的是
空 204，于是判成 `portal`；二是数据绕开 MM 自起，NM 看到 `qrtr0:gsm:disconnected`。
改法是 connectivity uri 换成国内可达的、`response=` 留空，再把 `qrtr0` 设 unmanaged。
根本解决还是得靠 modem 稳定注册。

**37. 商店和输入法装不上**

磁盘 91% 满了。先清盘再看别的问题。

## 七、工具和环境

**38. 多台设备一起连着，命令刷错机器**

`adb` 和 `fastboot` 的破坏性命令都要带 `-s <序列号>`。注意 adb 的序列号和
fastboot 的序列号不是同一个东西。

**39. 用 sudo 编译过一次，之后普通用户编译全挂**

`include/config/kernel.release` 一堆 Error 2。
`sudo chown -R $(id -un):$(id -gn) <内核树>` 修回来。

**40. 树外模块 vermagic 对不上**

编译要带 `ARCH=arm64 CROSS_COMPILE=aarch64-linux-gnu-`，编完 `modinfo` 看一下
vermagic 跟 `uname -r` 一致。另外 WSL 里的 vmlinux 配置要是和跑着的内核不同
（比如 PSI 开关不一样），模块会报 `psi_memstall_enter undefined`，那就只能全量重编。

## 最后，几条比技术更值钱的

一次只改一个变量，先跑对照组。改两个东西出问题就白改，还得倒回去重来。

「写进去了」和「生效了」是两回事。参数存在、函数返回 0、debugfs 里有个数字，
都不代表硬件真吃到了。我们最后是靠 `pr_info` 把 `level_count` 和实际 corner 打出来，
才确定下限到底有没有生效。

负面结果也要留证据。这个项目里「排除了某个假设」的日志，和「某功能可用」的日志
一样值钱，不然下次有人会把同样的坑再踩一遍。

固件和校准文件不要猜。一个「看起来对」的假文件，比缺文件危险得多。
