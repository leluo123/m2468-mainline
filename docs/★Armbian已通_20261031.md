## 关键陷阱：rawdump 只有 128 MB，ESP 必须做 128 MB

**这是之前一整轮失败的根因**：

```
rawdump 分区(sda22):  262,144 扇区 = 128 MB
                        但 fastboot getvar partition-size:rawdump 报 0x10000000 = 256 MB ← 骗人
我原来刷的 ESP:        268,435,456 字节 = 256 MB
                      → 每次刷机溢出 128 MB 到 sda23 头部
                      → userdata 的 ext4 超级块被 ESP 内容覆盖
                      → initramfs 报 "no rootfs found"
                      → Android 报 veritymode = eio
```

**正确做法**：ESP 镜像必须 **正好 134,217,728 字节（128 MB）**。
ESP 实际只用 16 MB（内核 14.7MB + initramfs 1MB + dtb 134KB），128MB 绰绰有余。

生成脚本：`ksuwork/make_esp128.sh`（`truncate -s 128M` + `mkfs.vfat -F 32` + 拷三个文件）

## systemd 起不来 → chroot bash 方案

**根因**：`/sbin/init` 是 systemd，它要求自己是 PID 1。
initramfs 里用 `setsid chroot /newroot /sbin/init &` 时，PID 1 是 initramfs 的 init，
systemd 检测到不是 PID 1 就**静默退出**（连错误都不打）。

**为什么不用 switch_root**：`switch_root` 的 `mount --move /dev` 会让 initramfs 里创建的
USB gadget 串口 `ttyGS0` 消失 → 新系统拿不到控制台。

**采用的方案**（`_ird_check/init` 第 152-165 行）：

```sh
else
  log "chroot init DIED within 10s - falling back to ROOTFS bash (Armbian userspace)"
  mount --bind /dev/pts  /newroot/dev/pts  2>/dev/null
  mount -t tmpfs tmpfs   /newroot/run      2>/dev/null
  if [ -c "$GS" ]; then
    exec chroot /newroot /bin/bash --login < $GS > $GS 2>&1
  else
    exec chroot /newroot /bin/bash --login
  fi
fi
```

**代价**：没有 systemd 服务（网络、SSH、定时任务都没有），但 apt/gcc/python 全部可用。
**下一步**：要做完整 systemd，需要在 rootfs 里加一个服务重新创建 USB gadget 后再 switch_root。

## 踩过的坑（按代价排序）

1. **rawdump 真实大小 128MB ≠ fastboot 报的 256MB** — 导致连续多轮刷机都在悄悄破坏 userdata
2. **systemd 在 chroot 里静默退出** — 必须 fallback 到 bash，或改 switch_root
3. **`fastboot` 是 Windows 程序，不认 WSL 路径** `/home/shrp/...` — 必须先复制到 C 盘
4. **USB 链路不稳** — `Write to device failed (no link)` 要重试，别当设备坏了
5. **`make olddefconfig` 会删配置** — `CONFIG_QCOM_GPI_DMA` 整项消失且连带关掉 `CONFIG_EFI_ZBOOT`
6. **`.config` 会被意外裁剪**（322KB → 241KB）— 改前必须备份

## 2026-10-31 后续：systemd 已跑起来（E34 switch_root）

### 从 chroot 改成 switch_root

```yaml
E33: chroot /newroot /sbin/init  → systemd 检测到不是 PID1 → 静默退出 → fallback bash
E34: exec switch_root /newroot /sbin/init  → systemd 真正成为 PID 1
```

### 关键：怎么解决「switch_root 后串口消失」

原注释说的坑是真的：`switch_root` 的 `mount --move /dev` 会让 initramfs 里创建的
USB gadget 串口 `ttyGS0` 消失。

**解法（两层保险）**：

1. **switch_root 时 /dev 用 `mount --bind` 而不是 `mount --move`**
   —— devtmpfs 保持挂载，ttyGS0 短期还在
2. **Armbian 里装一个 systemd 服务重新建 gadget**
   `/etc/systemd/system/usb-gadget-console.service`
   `/usr/local/bin/m2468-usb-gadget.sh`
   —— systemd 启动时通过 configfs 重新绑 UDC，重新生成 ttyGS0

### 又一个坑：getty 抢跑

```
systemd 启动 → serial-getty@ttyGS0 尝试启动 → 但 ttyGS0 还不存在（gadget 未建）→ 失败
             → usb-gadget-console.service 建好 gadget → ttyGS0 出现
             → 但 getty 已经放弃，串口没人接
```

**修法**：
- gadget 脚本末尾加 `systemctl start serial-getty@ttyGS0.service`
- getty 的 drop-in 加 `Restart=always` + `RestartSec=3`

Armbian 给 Orange Pi 5 配了蓝牙服务，本机没这个硬件，导致 `degraded`：

```bash

systemctl reset-failed
# → is-system-running = running
```
