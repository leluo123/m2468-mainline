# 追加：SPMI 用户态/固件态读取的两条路都堵了（2026-10-29 12:30）

## 本轮尝试（Mu 里的 SpmiResetDxe 写文件）

### 设计
在 Mu 的 DXE 阶段跑一个驱动，扫描 SPMI 全部关键寄存器，把结果写到 ESP 的 `\EFI\spmi.txt`，重启后从 Android 读。

理由：Mu 阶段在内核 `ioremap` 之前，不存在 `/dev/mem` 冲突；写文件比 `DEBUG()` 可靠（DEBUG 只在崩溃时才被 crash handler 倒出来）。

### 结果：**文件没写出来**

`rawdump` 分区里搜不到 `SPMI PMIC ARBITER PROBE` 字符串。两次尝试：
1. Depex = `gEfiCpuArchProtocolGuid` → 文件不存在
2. Depex = `gEfiSimpleFileSystemProtocolGuid` → 文件仍然不存在

### 原因（已定位）

```
SpmiResetDxe (Depex: SimpleFileSystem)
    ↓ 等待
SimpleFileSystem (FAT)
    ↓ 依赖
DiskIo / Partition
    ↓ 依赖
UFSDxe → UFS 控制器
    ↓ 需要
PMIC 供电（VCC 2.95V / VCCQ 1.8V）
    ↓ 需要
PMIC 初始化（PmicDxe）
    ↓ 需要
SPMI arbiter 正常工作
    ↓ 需要
我们要读的东西
```

**这是一个闭环死锁**：要读 SPMI 需要写文件，写文件需要 UFS，UFS 需要 PMIC，PMIC 需要 SPMI。

`gEfiCpuArchProtocolGuid` 版本能早跑，但那时 FAT 还没装（找不到文件系统）；`SimpleFileSystem` 版本永远等不到（UFS 枚举失败）。

---

## 两条读取路径的完整结论

| 路径 | 结果 | 原因 |
|---|---|---|
| **内核用户态 `/dev/mem`（init + devmem）** | ✅ **成功读到 core VERSION = 0x70000000 和 cnfg/ch 全 0**；批量扫描时报 `Bus error` | 内核 `spmi-pmic-arb` 已 `ioremap` 该窗口，用户态再映射同一物理区冲突。单点读能过，连读会挂 |
| **Mu DXE 写 ESP 文件** | ❌ 文件写不出来 | 死锁（见上）：SimpleFileSystem 要等 UFS，UFS 要等 PMIC |
| **Mu `DEBUG()` 上屏** | ⚠️ 需崩溃才可见 | DEBUG 走 Qcom debug buffer，只有 crash handler 会把它倒到屏幕；PmicDxe 关掉后 Mu 不崩（除 Buttons 那个点），看不到 |

---

## 已经拿到的关键事实（不变）

```
SPMI core VERSION  = 0x70000000        arbiter v7
cnfg+0xE60..0xE70  = 0 0 0 0 0         EE 配置全空
ch0/ch1 CMD/CONFIG/STATUS = 0          无 pending 命令，STATUS 非 busy
```

**结论：ABL 没有初始化 SPMI arbiter。** SPMIDxe 期望接手一个已配置好的状态（APSS 拥有通道、映射表已建立），遇到全 0 就报 `SPMI bus busy`。

---

## 下一步（三条，按可行性排序）

### 路线 1：让 Mu 的 DEBUG 输出真正上屏（最快见效）

Mu 崩在 `ButtonsDxe` 之后（`0xC3C8C5AC`）——**这意味着 crash handler 会执行，debug buffer 会被倒到屏幕**。

**做法**：把 `SpmiResetDxe` 的 Depex 改回 `TRUE`（最早执行），保留 `DEBUG()` 输出。即使随后 Buttons 崩，crash dump 会把我们的 SPMI 数据一起打出来。

**风险**：debug buffer 容量有限（通常 4-16KB），我们的扫描输出约 8KB，可能被截断。**先把扫描范围缩小到最关键的 20 个寄存器**（core VERSION + cnfg 0xE60~0xE70 + ch0~ch3 的 CMD/STATUS），控制在 1KB 内。

### 路线 2：Mu 的 UEFI Shell 交互读

Mu 支持 Shell（`mm` 命令可直接读写物理地址）。通过串口（`SimpleTextInOutSerial`）或 USB 键盘操作。

**前提**：需要一个串口或 USB 键盘。备选机没有专用串口，但 USB OTG 键盘可能可用。

### 路线 3：从 ABL/XBL 逆向 SPMI 初始化序列（根治，最慢）

`xbl_a` 里确有 SPMI 代码（15 条字符串 + `0xC42D000` 常量 @ 文件偏移 `0x5e2aa`）。反汇编 `0x5e0aa` 附近，找出 ABL/XBL 写 EE 配置的具体序列，然后在 Mu 里复刻。

**估算**：1–2 天。

---

## 建议的下一步动作（路线 1）

1. `SpmiResetDxe.c` 里把扫描范围缩到 20 个关键寄存器（输出 < 1KB）
2. Depex 改回 `TRUE`
3. 输出只用 `DEBUG(DEBUG_ERROR, ...)`
4. 刷入 → Mu 崩在 Buttons → crash dump 带出我们的数据 → 拍照

这一轮几乎肯定能看到数据，因为 Buttons 那个崩溃点已经被证明会触发 crash handler。
