## 真正的根因链（我前面判断错了 4 次）

| 我的错误判断 | 实际 |
|---|---|
| DT 缺 `dmas` → PCIe 失败 | ❌ 那是**触摸**的问题（SE4），跟 PCIe 无关 |
| 要加 `pci-pwrctrl` 节点 | ❌ Mu DT **本来就有** `pcie@0{wifi@0{...}}` |
| 要改 9 路 supply 的 phandle | ❌ 全部正确有效（ldo0=0x5b…ldo9=0x9a） |
| WCN7850 没上电（对）→ 要手写驱动 | ⚠️ 对，但只需**加载两个现成的 .ko** |

**真实因果：**

```
pwrseq-qcom-wcn.ko 没加载
  → pwrseq 的 regulators-enable count = 0
  → WCN7850 的 7 路电全关（vdd/vddio/vddio1p2/vddaon/vdddig/vddrfa1p2/vddrfa1p8）
  → 芯片没电，PCIe link training 失败
  → qcom-pcie: cannot initialize host（无限重试）

加载 pci-pwrctrl-pwrseq.ko（pcp.ko）
  → 它是 pwrseq 的消费者，pci_pwrctrl_power_on_devices() 触发上电
  → regulators-enable count = 1
  → PCIe Gen.2 x2 link up → 17cb:1107 出现
```

**关键代码位置**（`drivers/pci/controller/dwc/pcie-qcom.c:1424`）：

```c
static int qcom_pcie_host_init(struct dw_pcie_rp *pp)
{
    qcom_pcie_perst_assert(pcie);            // 1. PERST# 拉低
    pcie->cfg->ops->init(pcie);              // 2. PHY/时钟
    qcom_pcie_phy_power_on(pcie);            // 3. PHY 上电
    pci_pwrctrl_create_devices(pci->dev);    // 4. 为 DT 子节点建 platform device
    pci_pwrctrl_power_on_devices(pci->dev);  // 5. ★ 调 pwrseq 上电
    qcom_pcie_perst_deassert(pcie);          // 8. PERST# 释放
}
```

## 踩过的坑（四个，都值得记）

### 坑 1：initramfs 的 busybox 里没有 insmod

initramfs 的 `/bin` 只有 18 个 applet：
```
ln hexdump sh uname mount ls mkdir echo cat mdev dd getty dmesg
busybox sleep umount ps free
```
**没有 insmod / modprobe / cp / tr / lsblk。**

所以在 initramfs 的 init 里写 `insmod` 一定静默失败（`/bin/busybox --install -s /bin` 也补不出来，因为 busybox 没编进这些 applet）。

**教训：initramfs 阶段不要指望 insmod；模块加载放 rootfs 的 systemd service。**

### 坑 2：ESP 的 initramfs 改了，但 initramfs 阶段的 init 看不到日志

`echo > /dev/tty0` 和 `> /dev/ttyGS0` 在 initramfs 阶段都可能不显示（串口是 Linux 起来后才枚举的 gadget）。
要看 initramfs 日志只能 `> /dev/kmsg` 然后起来后 `dmesg`。

### 坑 3：ESP 分区不能直接 mount，但能 dd

```
mount -t vfat /dev/sda22 /mnt/esp        → can't read superblock（被 UEFI 占用）
dd if=/dev/sda22 of=/tmp/esp.img bs=1M count=128   → 767 MB/s，秒完成
mount -o loop,ro -t vfat /tmp/esp.img /mnt/esp    → OK
```

**这是往设备里送大文件的最快通道：ESP 是 FAT32，dd 出来 loop 挂载就能读，反向写回也行。**

### 坑 4：串口传大文件的真实速率

- 设备端 shell 会 echo 每条命令，实际速率减半
- 4.1MB base64 实测只有 **123 B/s**（10 分钟走 1.8%）→ 不可行
- 11KB base64 只要 **33 秒**（340 B/s）→ 小文件可行

**大文件走 ESP/dd，小文件走串口。**
