# m2468 触摸屏排查 —— 2026-10-30

> 结论先行：触摸是 **Goodix GT9916，走 SPI**，不是 i2c。
> 卡点是 **CONFIG_QCOM_GPI_DMA=m**（模块没进 initramfs），导致 SPI 主控拿不到 DMA 通道。

---

## 一、硬件真相

| 项 | 值 | 来源 |
|---|---|---|
| **触摸 IC** | Goodix（`goodix,brl-d` / `goodix,gt9916`） | 原厂 dtbo + Mu dtb |
| **总线** | **SPI**（`spi-max-frequency = 15MHz`，reg=0） | 原厂 dtbo |
| **GENI 实例** | `a90000`（`geniqup@ac0000` 下） | Mu dtb |
| **reset-gpio** | tlmm 24（0x18） | 两处一致 |
| **irq-gpio** | tlmm 25（0x19） | 两处一致 |
| **分辨率** | 1264×2780 | 面板原生 |
| **供电** | avdd + iovdd（L9B / L12B） | 原厂 dtbo |

**注意**：`tms_thn31@28` 是 **NFC**（`compatible = "tms,nfc"`），不是触摸。别搞混。

## 二、根因链（已逐条实测验证）

### 1. 初始症状
```
i2c 设备: 只有 0-0028（NFC），没有触摸
spi 设备: 空
dmesg:    geni_i2c a90000.i2c: error -ENXIO: Invalid proto 1
```

**`Invalid proto 1`** = GENI 总线被硬件/固件配置成 SPI 模式，但 dtb 声明成 i2c → 驱动拒绝 probe。

### 2. dtb 改造（已完成）
Mu dtb 里触摸节点存在但配置错：
```dts
i2c@a90000 { status = "okay";          // 错：硬件是 SPI
  touchscreen@5d {                     // 错：SPI 设备不该在 i2c 下
    compatible = "goodix,gt9916";
    reg = <0x5d>;                      // 错：SPI 应该是 0
    touchscreen-size-x = <0x438>;      // 错：1080（别的机型模板）
    touchscreen-size-y = <0x960>;      // 错：2400
  };
};
spi@a90000 { status = "disabled"; }    // 错：这才是该启用的
```

**改成**：
```dts
i2c@a90000 { status = "disabled"; }
spi@a90000 { status = "okay"; #address-cells = <1>; #size-cells = <0>;
  touchscreen@0 {
    compatible = "goodix,gt9916";
    reg = <0x00>;
    spi-max-frequency = <0xe4e1c0>;    // 15MHz
    reset-gpios = <&tlmm 24 GPIO_ACTIVE_LOW>;
    interrupts  = <&tlmm 25 IRQ_TYPE_EDGE_FALLING>;
    touchscreen-size-x = <0x4f0>;      // 1264
    touchscreen-size-y = <0xadc>;      // 2780
    status = "okay";
  };
};
```

### 3. 改造后的新症状
```
platform a90000.spi: deferred probe pending:
  geni_spi: Failed to get tx DMA ch
```

**`Invalid proto` 消失了**（说明 SPI 模式正确），但 DMA 通道拿不到。

### 4. 真正的根因
```
CONFIG_QCOM_GPI_DMA=m     ← 编译成模块
```

- initramfs 里没有 `gpi.ko`
- 内核启动时不会加载模块
- → `dma-controller@a00000` 没有驱动绑定
- → `spi@a90000` 请求 DMA 通道失败

**修复**：`CONFIG_QCOM_GPI_DMA=y`（内建），重编内核。

## 四、关键教训

1. **FdtBlob 里的 dtb 可能和设别上跑的不一致** —— 当前 FdtBlob 是 `meizu,m2468-noprobe-test`（实验版），设备跑的是 12:37 编的正式版。改 dtb 前必须先确认 panel compatible 正确，否则编出来的 Mu 点不亮屏。

2. **`dma-channel-mask = 0x1e` 不是"禁用通道 0"** —— 语义是"通道 1-4 被 TrustZone 锁定"。同一 QUP 组里所有工作正常的节点（i2c@a80000 等）都用 channel 0，所以 channel 0 是对的。改之前先看同组其他节点的写法。

3. **GENI 是一套硬件，多种协议** —— `i2c@xxxx` 和 `spi@xxxx` 是同一个物理控制器的两个 DT 节点，只能启用一个。选错就报 `Invalid proto N`。

4. **`=m` 的驱动在 initramfs-only 环境里等于不存在** —— 要么改 `=y`，要么把 .ko 塞进 initramfs。
