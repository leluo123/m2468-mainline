## 一、今晚修复完成的功能

### ✅ 1. 电池百分比（彻底解决）

**根因**：ADSP remoteproc 无固件（`qcom/sm8550/meizu/adsp.mbn` 缺失），`qcom-battmgr-bat` 拿不到 capacity。

**解决过程**（有据可查，不是猜的）：
1. Flyme `dsp` 分区（ext4）→ 只有 `adsp/*.so`，**没有 .mbn** ✗
2. `vendor/firmware` → 只有 a740_zap / goodix / camera ✗
3. **`modem` 分区（FAT16, 263MB）→ `image/adsp.mdt` + `adsp.b00~b57`（31MB）✓ 找到了**

**关键知识**：mainline 的 `qcom_mdt_load()` 原生支持 `.mdt + .bXX` 分片格式（`mdt_loader.c: qcom_mdt_bins_are_split`）。所以：
- `adsp.mdt` 改名为 `adsp.mbn` 放进 `/lib/firmware/qcom/sm8550/meizu/`
- 连同 `adsp.b00 ~ adsp.b57` 一起放
- DT 里 `&remoteproc_adsp` 的 `firmware-name` 不用改（写的就是 `adsp.mbn`）

**验证**：
```
remoteproc1 state = running
dmesg: qcom,apr 6800000.remoteproc:glink-edge.adsp_apps: GPR RX #10 opcode=0x02001003
       qcom-prm gprsvc: q6prm_set_lpass_clock: clk_id=780
battery capacity = 56%  ✓
```

**持久性**：固件在 rootfs 的 `/lib/firmware`，重启自动加载。

**注意**：固件**不能**放在 ESP 里（见下方"ESP 陷阱"）。

### ✅ 2. UI 启动（greetd/phoc）

**根因 1**：`/dev/shm` 权限是 755，应为 1777 → `phoc: Failed to allocate shm file for keymap` 导致 greeter 退出。

**修复**：
- `chmod 1777 /dev/shm`
- `/etc/fstab` 加 tmpfs 行
- 建 `fix-shm-perm.service`（`Before=greetd.service`，oneshot chmod），已 enable

**根因 2**：`seatd` 未安装 → `[libseat] No backend was able to open a seat`。装 `seatd` 并修 seat 权限。

### ✅ 3. dmabuf heaps（内核配置）

**原状**：`# CONFIG_DMABUF_HEAPS is not set`、`# CONFIG_UDMABUF is not set` → `phoc: Linux dmabuf support unavailable`、`/dev/dma_heap/` 不存在。

**修复**（E37 内核）：
```
CONFIG_UDMABUF=y
CONFIG_DMABUF_HEAPS=y
CONFIG_DMABUF_HEAPS_SYSTEM=y
CONFIG_DMABUF_HEAPS_CMA=y
CONFIG_TEE_DMABUF_HEAPS=y
```
验证：`/dev/dma_heap/` 下出现 `system`、`default_cma_region`、`reserved`、`adsp-rpc-remote-heap`。

## 二、花屏 —— 根因已定位（待验证）

### 症状
滑动时**右侧中间偏上**局部花屏，位置固定，静态画面不明显。

### 根因
`drivers/gpu/drm/msm/msm_drv.c:61`

```c
bool msm_dsc_stock_content;          // ← 默认 false！
module_param(msm_dsc_stock_content, bool, 0644);
```

`drivers/gpu/drm/msm/dsi/dsi_host.c:1959`

```c
if (msm_dsc_stock_content)
    dsc->first_line_bpg_offset = 13;   // 原厂值
```

代码注释原文：

> Sleep-wake mosaic content knob: stock derives `first_line_bpg_offset` **13** from a slice-height tier table (`_get_dsc_v1_2_bpg_offset`, 20 rows -> <=30 tier), the VESA 1.2 444 table here gives **12** — **the root item of the S2 content diff** (`initial_dec_delay` 526/549, `nfl_bpg_offset` 1294/1402 and `scale_increment_interval` 488/469 all follow from it).

**含义**：DSC 码率控制参数整族偏移 → 面板解码出局部错块 → 局部花屏。这解释了为什么 `underrun: 0`、`vsync` 正常（链路没坏，参数错）。

### 修复
`msm_drv.c:61` 改为 `bool msm_dsc_stock_content = true;` → E44 镜像。

### 原厂对照（dtbo `xjmz_amoled_tianma_cmd`）
```
qcom,mdss-dsc-bit-per-pixel      = 8
qcom,mdss-dsc-bit-per-component  = 10
qcom,mdss-dsc-slice-per-pkt      = 2      ← 我们用 MIPI_DSI_MODE_DSC_ALL_SLICES_IN_PKT 实现
qcom,mdss-dsc-version            = 1.2
qcom,mdss-dsc-slice-width        = 632    ← 和我们一致
qcom,mdss-dsc-slice-height       = 10     ← 和我们一致（10 是原厂值，不是 bug）
qcom,mdss-dsi-panel-framerate    = 0x78 = 120Hz
porch: h-pulse 16 / h-back 32 / h-front 100 / v-pulse 18 / v-back 32 / v-front 100
       ← 和我们驱动完全一致
```

## 四、踩过的坑（重要，避免重复）

### ★ 坑 1：ESP 里不能放多个固件文件
- 128MB ESP 只放 `EFI/BOOT/BOOTAA64.EFI` + `initramfs.cpio.gz`（2 个文件）→ **稳定启动**（20-35 秒出串口）
- 往里面加 `fw/` 下 60 个 ADSP 固件文件 → **启动不稳定，多数时候起不来**
- 结论：固件走 rootfs 的 `/lib/firmware`，不要走 ESP

### ★ 坑 2：Mu 用的是预编译 dtb，不是 Linux 树的 .dts
- **实际文件**：`/home/shrp/Mu-Silicium/Platforms/Meizu/m2468Pkg/FdtBlob/sm8550-meizu-21note.dtb`
- 改 `arch/arm64/boot/dts/qcom/sm8550-meizu-21note73.dts` **完全无效**（不参与 Mu 编译）
- 验证方法：设备上 `cat /proc/device-tree/soc@0/remoteproc@6800000/status`

### ★ 坑 3：ESP 尺寸必须 128MB
- 改成 256MB（填满 rawdump 分区）→ **完全无法启动**
- 128MB 正常

### ★ 坑 4：CMA 不能乱加大
- `CONFIG_CMA_SIZE_MBYTES` 从 32 改 512 → **完全无法启动**
- 且实测 CmaFree 还有 40MB，CMA 根本不是瓶颈

### ★ 坑 5：串口有 getty 争抢
- `getty@ttyGS0.service` 和 `serial-getty@ttyGS0.service` 同时抢 ttyGS0
- 导致登录输入被反复切断（`Login incorrect`）
- 修复方向：禁用 `getty@ttyGS0.service`

### ★ 坑 6：串口脚本要先探活
- 直接发命令会被 login banner 吞掉
- 正确做法：先发 `echo MARK` 确认拿到 prompt，再发实际命令
- 输出要写文件再读（长输出会被折叠）
