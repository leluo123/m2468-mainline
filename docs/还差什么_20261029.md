# 距离「跑通 mainline Linux」还差什么

**日期**：2026-10-29 01:15
**设备**：魅族 21 Note（m2468 / SM8550），已回滚 Android，随时可再刷

---

## 一、先定义「跑通」

「跑通 Linux」有三档标准，现在是第 2 档：

| 档 | 标准 | 状态 |
|---|---|---|
| 1 | 内核能启动、能出日志 | ✅ 早已达成 |
| 2 | **能启动 + 能交互 + 能读写存储 + 有日志通道** | ✅ **今晚达成** |
| 3 | 能日常使用（出图、触摸、WiFi、音频、可关机） | ❌ 还差 5 件事 |

---

## 二、已经跑通的（有实测证据）

| 子系统 | 证据 |
|---|---|
| **Mu-UEFI 启动链** | ABL → BootShim → Mu → ESP/BOOTAA64.EFI → Linux 7.3.0 |
| **UFS 存储** | `sd 0:0:0:0` 6 个 LUN，508 GB，23 个分区，`/dev/sda~sdf` 全部就绪 |
| **USB 串口 console** | `COM16` = `VID_0525&PID_A4A7\M2468`，busybox 交互 shell |
| **内存** | `free` = 14.2 GB 全识别 |
| **主 SMMU** | `15000000.iommu` 正常 |
| **GPU SMMU** | `3da0000.iommu` SMMUv2 / 22 context banks / stage-1 48→36 bit |
| **GPU 本体** | `3d00000.gpu` 绑定 `adreno` 驱动，GMU 进 iommu group 1 |
| **Display 控制器链** | `msm-mdss` → `msm_dpu` → `msm_dsi` → `msm_dsi_phy` 全部绑定 |
| **日志三通道** | USB 串口 / 屏幕 tty0 / `/dev/kmsg` |
| **关屏** | Mu 在交接 OS 前调 `SetDisplayPowerState(Off)`（已编进 Mu，待复核） |

**关键突破在两次「模块腿」**：
1. `CONFIG_PHY_QCOM_QMP_UFS=m` → 改 `=y`，UFS 通
2. `CONFIG_SM_GPUCC_8550=m` → 改 `=y`，GPU SMMU + GPU + 整条 display 控制器链一起通

## 三、还差的 5 件事（按重要性排序）

### 1. Panel 驱动 —— display 出图的唯一缺口 ★★★

**现状**：`/sys/class/drm/` 只有 `version`，没有 `card0`，`/dev/dri` 不存在。

**原因**：整条控制器链都 probe 成功了，但 **DSI 上没有可用的 panel**：
- DT 里挂的是 `boe,meizu20-amoled-fhd`（m2381 魅族 20 的面板）
- m2468 实屏是 **XJMZ AMOLED TIANMA**（Android cmdline：`xjmz_amoled_tianma_cmd`）
- 没有匹配的 panel 驱动 → 没有 connector → DRM 不注册 card

**要做**：
- 写一个 `panel-xjmz-amoled-tianma.c`（`drm_panel` + DSI 初始化序列）
- 需要从原厂 `vendor_boot.img` 或反编译 `msm_drm` 里抠出 **panel init sequence**（几十条 DSI 命令）
- 或者先试 `panel-simple` + **手工 DSI 时序**，能不能点亮到「有画面」的程度

**难度**：中高，是纯逆向 + 大量试错，但不需要硬件改动。

**为什么昨晚试 `CONFIG_DRM_PANEL_BOE_MEIZU20=y` 会崩**：面板型号不对，init sequence 打进去直接卡死 DSI。

---

### 2. 真正的根文件系统 ★★★

**现状**：跑的是 initramfs 里的 busybox，内存盘，掉电即失。

**要做**：
- 在 UFS 的 `/dev/sda23`（userdata，388 GB）上建 ext4 或 f2fs
- 内核 cmdline 从 `rdinit=/init` 改成 `root=/dev/sda23 rootwait`
- 装一个最小发行版（Debian/Ubuntu arm64 或 Alpine），再上 systemd

**难度**：低-中。UFS 已经能读写，这一步是纯软件工程，没有硬件坑。

**注意**：`fs/fat/inode.c:1659` 那个坑只影响 FAT32 挂 4096 逻辑块设备；用 ext4/f2fs 不受影响。

---

### 3. 触摸屏 ★★

**现状**：Mu 只把物理按键（电源/音量）映射成 ConIn，触摸完全没接。

**要做**：
- 找到触摸 IC 型号（大概率是 Goodix 或 Novatek，走 I2C/SPI）
- 内核里有对应驱动就改 DT 加节点；没有就写驱动

**难度**：中。找不到 IC 型号会卡很久，需要拆机或从原厂 dtbo 里抠。

---

### 4. WiFi / 蓝牙 ★★

**现状**：`1c00000.pcie: qcom-pcie: cannot initialize host`（PCIe 控制器起不来），WiFi 大概率挂在这条总线上。

**要做**：
- 先修 `1c00000.pcie`（很可能还是「模块腿」——查 `CONFIG_PCIE_QCOM*` 是不是 `=m`）
- 再看 WCN6855/WCN7850 的固件和驱动

**难度**：中。步骤 1 可能一条配置就解决，后面是固件问题。

---

### 5. CPU 频率调节 ★

**现状**：`17d91000.cpufreq  qcom-cpufreq-hw: Failed to find icc paths`

**原因**：DT 里 cpufreq 节点缺 `interconnects` 属性，而且日志显示 `gcc` 的 `sync_state()` 在等 iommu 和 i2c，形成依赖环。

**要做**：
- GPUCC 修好后，iommu 已经起来了，**这个可能已经自己好了**（本次启动 deferred 里 pcie 就自己消失过）
- 若还没好，给 cpufreq 节点补 `interconnects` / `interconnect-names`

**难度**：低。影响的是性能和功耗，不影响能不能跑。

---

## 四、还有这些（不影响「能跑」，但日常要用）

| 项目 | 说明 |
|---|---|
| 音频 | WCD9385 codec，需要 ADSP 或 SOF |
| Modem / 电话 | 需要 PIL + ADSP + modem firmware，难度很高 |
| 摄像头 | `i2c-qcom-cci ac15000/ac16000: -110`（CCI 总线），先修 CCI |
| 传感器 | 加速度/陀螺仪，I2C |
| 电源管理 | suspend/resume 基本没测过 |
| 关机/重启 | 目前只能硬重启，需要 PMIC 支持 |
| 充电 | 需要 `qcom,pmic-glink` 或 charger 驱动 |

---

## 五、下一步建议（如果继续做）

**优先级最高的两件事，都不需要碰硬件**：

1. **根文件系统**（3-4 小时能做完）
   - 一旦有了真实 rootfs + systemd，整个系统可用性会跳一个档
   - 而且能 `apt install` 工具，后续调试全在设备上完成

2. **Panel 驱动**（1-3 天，取决于能不能抠到 init sequence）
   - 这是唯一能「看见画面」的路
   - 先从原厂 `vendor_boot.img` 里的 `msm_drm` 或 `panel` 相关 ko 抠初始化序列

**建议顺序：先做 1，再做 2。** 因为 rootfs 做完后，panel 调试可以在设备本机上做（有 gcc、有 dmesg），效率高很多。
