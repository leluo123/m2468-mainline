# 魅族 21 Note (m2468) mainline 点屏成功 —— 2026-10-30

> 屏幕：天马 U8 / 1.5K / LTPO，1264×2780，ILI7838E DDIC
> 结果：msmdrmfb 点亮，显示 Ubuntu 24.04.4 rootfs 内容

---

## 一、可靠启动配方（两次验证）

```bash
# 1. 刷原厂三件套，让原厂驱动复位 panel
fastboot flash boot_b        boot.img
fastboot flash dtbo_b        dtbo.img
fastboot flash vendor_boot_b vendor_boot.img
fastboot reboot
# 等 recovery 起来（屏幕有显示 = panel 已复位）

# 2. 进 bootloader
adb reboot bootloader

# 3. 刷 mainline
fastboot flash boot_b   ★待刷_Mu_不关屏.img
fastboot flash rawdump  E25_panel_real.img
fastboot reboot

# 4. 等 40~60 秒，COM16 出现，进 Ubuntu

# 5. 点屏（关键）
echo Y > /sys/module/msm/parameters/zero_clkout_timing
echo 1 > /sys/class/graphics/fb0/blank
sleep 1
echo 0 > /sys/class/graphics/fb0/blank
```

**验证**：`cat /sys/class/graphics/fb0/name` 应返回 `msmdrmfb`

## 二、核心根因（今天最重要的发现）

### 1. panel 硬件状态跨刷机存活

```
mainline 驱动退出 → panel 留在"坏状态"
冷启动（电源键）→ 只复位 SoC，不复位 panel
重刷镜像       → 完全无效
只有原厂驱动   → 能把 panel 复位到正常态
```

**这解释了全部困惑**：同一个 E25 镜像，10:21 能起、10:53 起不来。因为 10:21 之前刚刷过原厂。

### 2. zero_clkout_timing 必须为 Y

| 项 | 值 |
|---|---|
| 源码 | `drivers/gpu/drm/msm/dsi/dsi_host.c:46` |
| 默认 | `static bool dsi_zero_clkout_timing;` = **false** |
| 影响 | `REG_DSI_CLKOUT_TIMING_CTRL` 写计算值 32/36 |
| 正确 | 写 **0**（原厂恒 0） |
| 后果 | 不设 → 黑屏但零错误；设 Y → 立即点亮 |

**E26 的失败教训**：把默认值改成 `= true` 编译进内核 → 启动崩溃。
正确做法：**sysfs 运行时写**（或 initramfs 里的 init 脚本写），不能用编译期默认值。

### 3. 两个 Mu 的区别（名字骗人）

| 镜像 | dtb panel compatible | status | 效果 |
|---|---|---|---|
| `★待刷_Mu_不关屏.img` | `meizu,m2468-panel` | **okay** | panel probe，能点屏 ✅ |
| `Mu-fuxi6.img`（"基线"） | `boe,meizu20-amoled-fhd` | **disabled** | 不 probe，只能 EFI VGA ❌ |

`Mu-fuxi6` 只是"关屏基线"——00:51 时我们要的是串口 shell，不需要点屏。

## 三、E25 内核配置（点亮时的完整状态）

```c
/* panel-meizu-m2468.c */
dsi->lanes      = 4;
dsi->format     = MIPI_DSI_FMT_RGB101010;      /* 30bpp，对齐原厂 */
dsi->mode_flags = MIPI_DSI_MODE_LPM |
                  MIPI_DSI_MODE_DSC_ALL_SLICES_IN_PKT;  /* 原厂 2 slices/pkt */
dsi->hs_rate    = 1200000000;                   /* 原厂 0x47868c00，不是 1094M */
dsi->dsc        = &ctx->dsc;                    /* 12 字段，8bpp/10bpc/632x10/2 slices */
```

**没有加** `NO_EOT_PACKET` / `CLOCK_NON_CONTINUOUS` —— 那是 BOE 屏（魅族20）的 PHY 参数，不适合天马 LTPO。

**初始化序列**：原厂 `timing@fhd_60` 的 100 条命令 / 1362 字节，逐字节一致（sha `eeebce92cc09`）。

## 四、已证伪的假设（别再走）

| 假设 | 证伪方式 |
|---|---|
| hs_rate 用 1094M（抄魅族20） | 原厂 dtbo `panel-clockrate = 0x47868c00` = 1200M |
| DSC 没配 | 日志 `DSC enabled: 8bpp/10bpc/1264x2780 slice 632x10 count=2` |
| DSC slice-per-pkt 是问题 | 已加 ALL_SLICES，wc 633→1265 |
| PHY timing 需覆盖 | ROUTE-H：主线算出值与原厂差 1-2，且都更安全；dts 注释"8倍过量"是错的 |
| reset gpio 没拿到 | E16 证明 `ptr` 有效、`is_err=0` |
| 三路供电不对 | 都是 regulator-fixed 1.8V，与原厂一致 |
| 是 TE 问题 | `frame_done_cnt=0` 是黑屏的结果，不是原因 |
| 文件被篡改 | 所有镜像 md5/mtime 均未变 |
| 冷启动能恢复 | 冷启动只复位 SoC，不复位 panel |
