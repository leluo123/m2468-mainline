## 二、三个根因（都有源码级依据）

### 2.1 display -110：不是 panel 驱动问题，是 **dispcc 缺席**

**错误认知**：以为要写 m2468 的面板驱动。
**实际根因**：`CONFIG_SM_DISPCC_8550=m`（模块），而 initramfs 里 0 个 `.ko`。

因果链：
```
dispcc-sm8550 是模块且无 .ko
  → clock-controller@af00000 永远没有 driver
  → sm8550.dtsi 里 mdss 的 clocks = <&dispcc …> 和 power-domains = <&dispcc MDSS_GDSC> 拿不到
  → msm-mdss 一直 -EPROBE_DEFER
  → driver core deferred probe 超时（drivers/base/dd.c:292）
  → 返回 -ETIMEDOUT = -110
```

**注意 -110 的真正来源**：`drivers/base/dd.c:285 driver_deferred_probe_check_state()`：
```c
if (!driver_deferred_probe_timeout && initcalls_done) {
    dev_warn(dev, "deferred probe timeout, ignoring dependency\n");
    return -ETIMEDOUT;      // ← 就是这里
}
```
**不是** `msm_drv.c:709`（那是 wait_fence 的 ioctl 路径，与 probe 无关）。

**已修复**：`CONFIG_SM_DISPCC_8550=y`，System.map 已确认编入。

**连带解释了两个现象**：
- `Fixed dependency cycle(s) with display-controller@ae01000` —— dispcc 缺席导致 fw_devlink 图成环
- SMMU translation fault（`SID=0x1c00`、`iova=0xb8b*`）—— mdss 没 probe 成功，没人建立 splash 区映射

### 2.2 USB 不枚举：configfs 从来没挂载

**错误认知**：以为缺 PHY 驱动、或 pmic_glink/pdr 的问题。
**实际根因**：init 脚本里只有 proc/sysfs/devtmpfs/debugfs/pstore 的挂载，**没有 `mount -t configfs none /sys/kernel/config`**。

因果链：
```
configfs 未挂载
  → /sys/kernel/config 只是 sysfs 上的空目录（fs/configfs/mount.c:144 只造挂载点）
  → mkdir /sys/kernel/config/usb_gadget/g1 在 sysfs 目录里 mkdir → EPERM
  → 全部错误被 2>/dev/null 吞掉
  → 没有任何 gadget 驱动绑上 a600000.usb
  → dwc3_gadget_pullup() 一次都没调用
  → D+ 上拉没做 → 主机连 connect 事件都收不到 → 没有黄口、没有未知设备
```

**这完美解释了四件事**：UDC 有 + TTYGS 空 + PC 全空 + dmesg 除 deferred 无异常。

**已修复**：init 加了 `mkdir -p /sys/kernel/config` + `mount -t configfs none /sys/kernel/config`。
**待验证**：configfs 是否真的挂上了（屏幕 `CONFIGFS_MNT` 那行）。

### 2.3 FAT 挂不上：这不是 bug，是内核硬性拒绝

**根因**：`fs/fat/inode.c:1659`
```c
if (logical_sector_size < sb->s_blocksize) {   // 512 < 4096
    fat_msg(sb, KERN_ERR, "logical sector size too small for device");
    goto out_fail;                              // error = -EIO
}
```

rawdump 分区的 BPB：`bps=512 / spc=1 / tot32=524288 / 卷标 MUESP`。
UFS 逻辑块 = 4096。**512 字节扇区的 FAT32 挂在任何 4K 逻辑块设备上永远失败**，Android 和 mainline 同一个原因。

**结论：mount 这条路是死的，别再为它刷机。** 要挂载必须 `mkfs.vfat -S 4096` 重做镜像。

## 三、今晚犯的三个错误（必须记住）

### 错误 1：回滚后忘了重刷 Mu，三次刷机全部空转

22:06 回滚时把 `boot_b` 刷成原厂 `boot.img`，之后 22:18 / 22:22 / 22:36 只刷 ESP 不刷 Mu。启动链是 `ABL → boot_b(Mu) → ESP 里 vmlinuz.efi`，boot_b 是原厂内核时 **ESP 里放什么都不看**，设备直接进 Android。这三次实验全部无效，白等 40 分钟。

**判据**：
```bash
adb devices && adb shell uname -a    # 有设备且含 -android13 → 实验无效
fastboot devices                     # 有设备 → 停在 fb，内核没起来
# adb 和 fastboot 都空 → mainline 正常在跑
```

### 错误 2：把「adb 空 + fastboot 空」误判成内核崩溃

mainline 没有 adbd，也不进 fb。两个都空是**正常运行**。今晚多次把这个状态当崩溃，导致无谓回滚重刷。

### 错误 3：跑 `make olddefconfig` 把 .config 打烂

`.config` 从 4698 行掉到 2789 行，八项门槛全部消失，8550 相关配置全没了。
**教训**：
- 改配置用 `./scripts/config --enable X`，改完先 `cp .config .config.pre_olddef`
- 如果跑 `olddefconfig`，之后必须检查 `grep -c '^CONFIG_' .config` 是否仍 > 4000
- 打烂立刻从 `/home/shrp/config.good_1740` 恢复

## 四、已彻底排除的错误方向（不要再试）

| 方向 | 为什么排除 |
|---|---|
| 写 BOE m2381 面板驱动（`boe,meizu20-amoled-fhd`） | 那是魅族 20 的屏，编进去内核未进 init 即崩；m2468 真实屏是 `xjmz_amoled_tianma_cmd`（天马，ILI7838E） |
| 删 `splash_region` 的 `iommu-addresses` | 会把 `dev_warn_once` 警告变成真实 SMMU translation fault 刷屏 |
| `mount -t vfat` rawdump | 512B 扇区 vs 4K 逻辑块，内核硬拒，Android 同样挂不上 |
| 改 PHY 配置解决 USB | PHY 已全部注册（`phy-88e3000.phy.5` 等 7 个），PHY 不是卡点 |
| 等更久让 sda22 出现 | 分区节点在 `add_disk` 里同步创建（`block/genhd.c:412`），不存在与时间无关 |
| 从 Android 读 mainline 的 pstore | `/dev/mem` 不存在；mainline 的 ramoops 报 `0x20000000@0x0` 地址解析成 0，本身可疑 |

## 五、下一步（按优先级）

### P0：确认 v25 init 的 configfs 是否挂上（一次刷机即可）

配置侧已全部确认正确，只剩 init 运行时。看屏幕这三行：

```
CONFIGFS_MNT: 1        ← 1 成功 / 0 失败
CONFIGFS_LS:  usb_gadget
bind: OK 或 FAIL
```

**分支处理**：
- `CONFIGFS_MNT: 0` → 挂载点或内核问题，检查 `mount` 返回值
- `CONFIGFS_MNT: 1` 但 `bind: FAIL` → UDC 被占（`CONFIG_USB_G_SERIAL=y` 可能在抢），把它设 `=n`
- `bind: OK` 但 `TTYGS:` 空 → acm 功能没生效，检查 `configs/c.1/acm.usb0` 符号链接
- `bind: OK` 且 `TTYGS:` 有值 → **USB 通了，从此不用拍屏**

### P1：验证 display 是否因 dispcc=y 而恢复

看 `DEF_N` 是否从 4 变 3（`msm-mdss` 不再 deferred），以及 dmesg 里 `-110` 是否消失。

如果 -110 消失但屏幕仍黑，再处理面板驱动；如果 -110 还在，说明还有别的 supplier 没 ready（下一步查 `sm8550.dtsi` 里 mdss 依赖的 interconnect：`&mmss_noc` / `&mc_virt` / `&gem_noc` / `&config_noc`）。

### P2：日志通道（不再作为主线）

如果 P0 的 USB 通了，这条自动解决。否则：
- rawdump 若要挂载，必须 `mkfs.vfat -S 4096` 重做（会丢掉 ESP 里的 BOOTAA64.EFI，需要重新放）
- 裸块 dd 到 200MB 偏移是合法的（文件只占 54.5–72 MiB，之后全空），失败原因待确认：注意 `dmesg > /tmp/d.txt` 若产出 0 字节，`dd` 复制 0 块仍返回 0（假成功）
